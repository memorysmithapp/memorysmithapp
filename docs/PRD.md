# PRD

What MemorySmith solves and delivers, and under which rule. How it is built is in [`ARCHITECTURE.md`](ARCHITECTURE.md); how a change reaches production is in [`SDLC.md`](SDLC.md).

## 1. Problem

Knowledge kept in Markdown is read by people and, more and more, written by AI agents. An agent handed a folder of notes does not know how that collection wants to be written: which folders exist and what goes in each, what a note of each kind looks like, which conventions the person follows. It guesses, and every session guesses differently, so the collection drifts the moment an agent starts writing in it. The structure lives in the person's head, not with the notes.

## 2. Audience

- **A person who keeps knowledge in notebooks** and works with an AI assistant. Needs to read and edit the notes comfortably, on a computer and on a phone, and to trust that what an agent wrote follows the notebook's own rules and says who wrote it.
- **The agent working for that person**, through Claude or ChatGPT. Needs to learn, from the notebook itself, where to write and how, and to be told when what it wrote will not read the way it meant.
- **The operator of the platform**, who approves subscriptions and keeps the service running, and reaches no customer content.

## 3. Goals and scope

**Delivers:**

- **Self-describing notebooks.** A notebook declares its Guidance (what it is for and how its notes are written), its folders with a description of what each keeps, and a Template per folder. Structure, order and Guidance are data, not convention.
- **A remote MCP server**, `https://mcp.memorysmith.app/mcp`, that serves the notebooks natively to an agent: it reads them and **writes in them**, obeying the Guidance and the Templates, with skills that teach the method (`design-notebook`, `write-notes`, `keep-files`, `convert-inline-tags`).
- **A web interface**, `memorysmith.app`, for the person: reading first, editing on the page that draws the note, the graph of links, search, history, attachments, sharing, export and import, print and PDF, in `en_US` and `pt_BR`.
- **Notes in a published Markdown notation**, the MemorySmith Markdown Specification, read the same way by the server, the interface and the agent's preview.
- **Kept files** a note embeds by name, sent whole by a person or an agent.
- **A trail of every change**, saying who wrote it and through which agent, and the history of each note.
- **Isolation by subscription**, with notebooks shared read-only across subscriptions on two consents.

**Deliberately does not:**

- Validate a note against its Template, or generate Markdown from a schema.
- Link notebooks to each other, or let one inherit from another.
- Restore what was deleted: deleting is definitive.
- Offer open sign-up: a subscription is requested and approved.
- Render raw HTML inside a note.

## 4. Principles

Code comments cite them by code. A principle that stopped holding keeps its code, marked removed.

- **PP1** In the end it is all Markdown: the server organises and serves notes, and never generates Markdown from a schema.
- **PP2** A notebook is autonomous: it describes itself in its own Guidance, with no inheritance and no links between notebooks.
- **PP3** A Template is a suggestion: the server never validates a note against it.
- **PP4** The server does not interpret content: it reads only the notation the specification declares ([`ARCHITECTURE.md` INV-05](ARCHITECTURE.md#inv-05-the-backend-reads-only-the-notation-the-specification-declares)).
- **PP5** Discovery is derived: the graph, the search and the facets are rebuildable from the notes.
- **PP6** _Removed: deleting is definitive, and the purge destroys every revision of what was deleted (RN-KNW-047)._
- **PP7** _Removed: an export is one archive holding a JSON document with the notes' Markdown, not a tree of files._
- **PP8** A complete model, a progressive interface: the interface shows a concept only when the person reaches its case.
- **PP9** Order is signal: the order of folders and notes is content, editable and exported.
- **PP10** An error is interface: every refusal says what to do next.

## 5. Ubiquitous language

The terms as the code names them. In the `pt_BR` locale, and only there, four are translated: **Guidance** is _Orientação_, **Template** is _Modelo de pasta_, **Notebook model** is _Modelo de caderno_, **Notebook** is _Caderno_. No other term is translated; _Note_ is _nota_, _Table_ is _tabela_ and _Dashboard_ is _painel_, the ordinary words, and the share profiles are named in ordinary words too: _Leitor do modelo_, _Leitor_, _Editor de conteúdo_, _Editor do caderno_.

## 6. Journeys

**A person sets up a notebook with an agent.** They connect Claude or ChatGPT to `https://mcp.memorysmith.app/mcp` and sign in. They describe what they want to keep; the agent reads the skill `design-notebook`, proposes the Guidance, the folders and their Templates, and creates them once the person agrees.

**An agent writes in a notebook.** It calls `whoami`, reads the Notebook Context, the Guidance and the Template of the folder, writes the note through `create_note` or `update_note`, reads the notices it gets back, and looks at the note with `preview_note` before handing the work over. Every write records the person and the agent.

**A person reads and edits.** On `memorysmith.app` they open the notebook, follow links and backlinks, search, look at the graph and the history, and edit a note on the page that draws it; the note saves as they type.

**A person shares, exports or prints.** They share a notebook read-only with a person of another subscription, export it to Transfers and import it elsewhere, or print a note and download it as a PDF.

## 7. Features and rules

Business rules are coded `RN-{AREA}-{NNN}`, append-only: a code is never renumbered or reused, and a rule that stopped holding keeps its row, marked removed. The areas are `SUB` (subscription, its life cycle and isolation), `ACC` (members, roles, notebook ceilings, accounts and sharing), `KNW` (knowledge: notebooks, folders, notes, Guidance, Templates and files), `DSC` (discovery: link graph, search, facets and the reading surface), `AUD` (audit trail and history), `AGT` (agent access: the MCP connector and its tools) and `PRT` (portability: export, import, transfers, uploads and rendering jobs).

## 8. Quality requirements

Declared so they become tests.

| Limit                           | Value                                                       |
| ------------------------------- | ----------------------------------------------------------- |
| Size of a note                  | 1 MB                                                        |
| A file kept in one call         | 4 MB                                                        |
| A file sent in parts            | 100 MB through signed addresses; 4 MB with the parts inline |
| Folders in a notebook           | 200                                                         |
| Depth of the tree               | 6 levels                                                    |
| Notes in a notebook             | No ceiling; the quota of the subscription bounds it         |
| Graph traversal                 | depth 3, at most 200 nodes                                  |
| Storage quota of a subscription | 500 MB, 1 GB or 2 GB                                        |
| Tables in a notebook            | 50                                                          |
| Rows in a table                 | 10,000                                                      |
| Size of a row                   | 4 KB                                                        |
| Columns in a table              | 50                                                          |
| Rows written in one call        | 50                                                          |
| Dashboards in a notebook        | 50                                                          |
| Components in a dashboard       | 24                                                          |
| Tables a dashboard draws from   | 10                                                          |
| Size of a dashboard definition  | 64 KB                                                       |
| Shortest automatic refresh      | 60 s                                                        |

**An action button** that carries an icon shows the icon and its word on a wide screen, and from 860 px down the icon alone, the word kept as its accessible name. The buttons around a note (Show and Copy Markdown, Edit and Read) show the icon alone at every width. The confirmations and cancels of a dialog or of an in-place question carry no icon and keep their word alone at every width, because an icon alone on a phone makes an irreversible answer easier to tap without reading. A button that spans the width of the screen on a phone keeps its word beside its icon there too, because the word is hidden to save room and that button is not short of it.
