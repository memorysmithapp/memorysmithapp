O review protege o leitor futuro, não o autor presente.

1. **Primeiro o desenho, depois o detalhe.** Comentário de arquitetura vem antes de comentário de estilo.
2. **Todo comentário diz o porquê**, não só o o quê.
3. Aprovação exige rodar o código quando o diff toca caminho crítico.
